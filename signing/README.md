# מערכת ההסכמים העצמאית של דור פיינה

מערכת שרת עצמאית, ללא שירות חתימות חיצוני. המקור נשמר ב־GitHub. GitHub Pages אינו מריץ את השרת הזה.

## איך משתמשים

1. נכנסים למסך הניהול עם סיסמה פרטית.
2. ממלאים פרטי לקוח, מייל, מועד ומקום האירוע, חבילה, שעות, מחיר, מקדמה והנחה.
3. מוסיפים אלבום הורים, הגדלת זכוכית, צילומי זוגיות או תוספת אישית. אפשר לסמן מתנות ללא חיוב. מחיר אלבום נוסף נקבע על ידך.
4. בודקים את הפרטים ויוצרים קישור אישי. מעתיקים ושולחים ללקוח בעצמכם; המערכת אינה שולחת הזמנות אוטומטית.
5. הלקוח רואה את כל הפרטים והתנאים ללא אפשרות לשנותם, מצייר חתימה, בוחר לגבי אישור פרסום, ומבקש קוד אימות למייל.
6. לאחר אישור וקוד תקף ההסכם ננעל. הלקוח ואתה מקבלים אותו PDF חתום. הלקוח מקבל הודעת תודה בעברית.
7. הסכם חתום ניתן להורדה בניהול. אם משלוח המייל נכשל, מופיע מצב המחייב בדיקה; החתימה והמסמך נשמרים.

שינוי עסקה לפני חתימה: מבטלים את הקישור הקודם ויוצרים חדש. קישור תקף שבעה ימים. חתימה אינה אישור לכך שהמקדמה שולמה. המקדמה נכללת במחיר הסופי ובדמי ביטול בהתאם לתנאים. זמני אספקה: סטילס 21 יום; וידאו 45 יום מבחירת השירים; אלבומים 30 יום מאישור העיצוב.

## הפעלה על שרת

נדרש שרת עם HTTPS, אחסון מתמשך פרטי וגיבוי, ושירות SMTP עם TLS. אין להעלות מפתחות או מסמכי לקוחות ל־GitHub. הגדרות לדוגמה נמצאות ב־`.env.example`; האפליקציה קוראת משתני סביבה, ולא טוענת קובץ `.env` בעצמה.

משתנים: `PUBLIC_URL` כתובת HTTPS מלאה ללא קו נטוי בסוף; `ADMIN_PASSWORD` סיסמה אקראית ארוכה (20 תווים לפחות); `OWNER_EMAIL=mmdorldor@gmail.com`; `SMTP_HOST`, `SMTP_PORT=587`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`; `COOKIE_SECURE=true`; `DATA_DIR` נתיב קבוע פרטי.

```sh
cd signing
python -m pip install -r requirements.txt
uvicorn app:app --host 127.0.0.1 --port 8787 --no-access-log
```

Docker: בונים מתוך תיקיית `signing`; מחברים volume קבוע אל `/data` ומזריקים משתנים דרך מנהל הסודות של השרת. פותחים את השרת רק מאחורי HTTPS. מפעילים worker יחיד: SQLite ומגבלות קצב מקומיות אינם מותאמים לפריסה מרובת שרתים. גם reverse proxy חייב להגביל בקשות ל־350KB ולא לרשום כתובות קישורי חתימה בלוגים. אין לחשוף את תיקיית `/data` או קובצי SQLite לציבור. יש לקבוע מדיניות גיבוי, שחזור ושמירת מידע לפני שימוש בלקוחות.

לפיתוח מקומי בלבד: `PUBLIC_URL=http://127.0.0.1:8787`, `COOKIE_SECURE=false`. בלי SMTP יצירת קישורי לקוחות חסומה במכוון. חיבור מייל דרך הצ'אט אינו מגדיר SMTP לשרת.

## בדיקות ומגבלות

```sh
python -m pip install -r requirements-dev.txt
python -m unittest -v test_signing
```

בדיקות משתמשות בלקוחות בדויים ובמשלוח מייל מדומה. הן בודקות הרשאות, גרסה נעולה, סכומים, מתנות, קוד אימות, חתימה חוזרת וביטול קישור. אינן מוכיחות מסירה של מייל אמיתי. לפני הפעלה: שלחו לעצמכם עסקת בדיקה, בדקו בשתי תיבות מייל את אותו PDF, בדקו גיבוי ושחזור ואת הנוסח המלא בכל חבילה.

אם משלוח חלקי או לא ודאי נכשל, המערכת אינה מנסה שוב אוטומטית, כדי לא לשלוח עותקים כפולים. המסמך נשמר והבעלים רואה `נדרשת בדיקה`; יש לבדוק מול שירות המייל ולשלוח ידנית את המסמך השמור לפי הצורך. אין סנכרון תשלומים, סליקה או מעקב מקדמות אוטומטי. זו חתימה מצוירת עם אימות מייל ותיעוד גרסה, לא חתימה באמצעות תעודה קריפטוגרפית.

## מיתוג

לוגו מקורי של העסק במסך הבעלים, במסך הלקוח וב־PDF. גופן Noto Sans Hebrew מצורף ברישיון OFL המצורף ב־`assets/OFL.txt`. התנאים נשמרו מהתבניות הקיימות; פרטי העוסק וכתובת העסק הוסרו לפי בקשת הבעלים.
