# המסלול החינמי: Google Apps Script

המסלול המומלץ לפעילות של עד הסכם ביום ועשרה בחודש. הקוד ב־GitHub, הריצה בחשבון Google שלך, והרשומות וה־PDF בתיקיית Drive פרטית. אין שירות חתימות, שרת בתשלום, SMTP, מפתח Gmail או קריאת תיבת הדואר.

## הגדרה ראשונית

1. בחשבון `mmdorldor@gmail.com` יוצרים פרויקט Apps Script. מוסיפים את `Code.gs` ואת `Data.gs` כסקריפטים, ואת `Index`, `Styles`, `Owner`, `Client` כקובצי HTML. קובץ הסקריפט הראשי יכול להיקרא גם `קוד.gs`; רק תוכנו חשוב. קובצי הבדיקות אינם מועלים לפרויקט Google.
2. בהגדרות הפרויקט מציגים את קובץ המניפסט `appsscript.json` ומעתיקים אליו את המניפסט שבמאגר.
3. במאפייני הסקריפט מגדירים `ADMIN_PASSWORD` עם סיסמה פרטית של 20 תווים לפחות. אפשר להגדיר `OWNER_EMAIL=mmdorldor@gmail.com`. אין לכתוב את הסיסמה בקוד, ב־GitHub או בצ'אט.
4. מריצים `setup_` בעורך. זו פונקציה פרטית; אינה נגישה מהלקוח. היא בודקת את החשבון, יוצרת תיקייה פרטית ושומרת את `DATA_FOLDER_ID`. אינה שולחת מייל. Google דורשת כאן אישור הרשאות Drive, Docs, משלוח מייל וידיעת כתובת החשבון. נדרשת פעולה של בעל החשבון להשלמת האישור.
5. פורסים כ־Web app: הפעלה כבעל החשבון; גישה למשתמשי הקישור (`Anyone`). לא משתפים את פרויקט הקוד או את תיקיית Drive. לפני פריסה לציבור יש לאשר במפורש את חשיפת יישום האינטרנט; ממשק הניהול דורש סיסמה, וכל הסכם מוגן בקישור אישי ובקוד מייל.
6. פותחים את כתובת `/exec`, נכנסים בסיסמה ומכינים עסקת בדיקה לעצמכם. בודקים תצוגת הסכם, קוד אימות, חתימה, PDF בעברית וקבלת שני המיילים. רק לאחר מכן שולחים קישורים ללקוחות.

קוד חדש ב־GitHub אינו מעדכן לבד את Google. לאחר שינוי קוד, מעתיקים את הקבצים המעודכנים ויוצרים גרסת פריסה חדשה. הכתובת נשמרת כאשר מעדכנים פריסה קיימת. אפשר להוסיף בהמשך קישור מתוך האתר הקיים.

## עבודה שוטפת

ממלאים פרטי לקוח ועסקה, מחיר, מקדמה, שעות, תוספות ומתנות. לוחצים **תצוגת ההסכם לפני יצירת קישור**, בודקים את כל התנאים, ומעתיקים ללקוח את הקישור שנוצר. ההזמנה אינה נשלחת אוטומטית.

הלקוח קורא את ההסכם הנעול, מצייר חתימה, בוחר לגבי אישור פרסום ומאמת קוד שנשלח למייל הרשום. בסיום נשמר PDF ונשלחים שני עותקים זהים: ללקוח עם הודעת תודה, ולך. חתימה אינה אישור שהמקדמה שולמה. אין כאן סליקה.

שינוי פרטים מחייב ביטול קישור קודם ויצירת חדש; אין עריכת הסכם לאחר חתימה. קישור תקף שבעה ימים, אך מסמך חתום נשאר נגיש לבעלים בתיקיית Drive ובמערכת. לא מוחקים רשומות אוטומטית. יש לקבוע שמירת מסמכים וגיבוי בהתאם לצורך.

מכסת Google לחשבון Gmail רגיל היא כיום 100 נמעני מייל ביום ומשותפת לפרויקטים אחרים בחשבון. תהליך רגיל צורך שלושה: קוד ללקוח ושני עותקי PDF. קודים חוזרים צורכים מכסה נוספת. המכסה אינה התחייבות לשירות: Google יכולה לשנות מגבלות, והאחסון נספר במסגרת המקום הפנוי ב־Drive. כשאין מכסה, המערכת חוסמת חתימה חדשה במקום להבטיח מייל שלא יישלח.

אם נשלח רק חלק מהמיילים או שהמשלוח לא ודאי, מופיע **נדרשת בדיקה**. המסמך החתום נשמר ולא מתבצעת שליחה חוזרת אוטומטית. מורידים את העותק בניהול ובודקים את מצב המשלוח לפני שליחה ידנית. אם ביצוע נקטע באמצע הפקת PDF, מצב **בטיפול** מחייב בדיקה שלך בתיקיית Drive לפני כל פעולה נוספת.

## בדיקות

```sh
node signing/google-apps-script/test_backend.cjs
```

עשר בדיקות עם שירותי Google מדומים: הרשאות ויציאה, מחירים ומתנות, חתימה חד־פעמית ועותקים זהים, גרסה והסכמה, קוד אימות ומגבלות ניסיונות, ביטול ופקיעת קישור, מכסת מייל, כשל משלוח, כשל PDF וחתימה ריקה. אין משלוח מייל אמיתי בבדיקות. PDF מדומה בבדיקות אינו בדיקת רינדור Google Docs; רינדור ומסירה אמיתיים דורשים הפעלה בחשבון שלך.

החתימה מצוירת ומאומתת במייל; נשמרים מועד, שם, אישור פרסום ותקצירי SHA256 של גרסת ההסכם ושל תמונת החתימה המקודדת. אין תעודת חתימה קריפטוגרפית. מסמכי המקור ב־Google Docs נשארים פרטיים לצד ה־PDF; הלקוח מקבל PDF בלבד.

תיעוד רשמי: [מכסות](https://developers.google.com/apps-script/guides/services/quotas), [פריסת יישום](https://developers.google.com/apps-script/guides/web), [MailApp — משלוח ללא קריאת תיבת דואר](https://developers.google.com/apps-script/reference/mail/mail-app).
